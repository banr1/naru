## ビルドと実行(リポジトリのルートで)
- `lake build` — naru コンパイラ(`compiler/`、lean_lib `Naru` + lean_exe `naru`。依存なし、冷えた状態で約 40 秒)。`lake build NaruStd` — Model 用 stdlib(`stdlib/Model`)。`lake build Model` — 生成 Model(C6。38 モジュールで 47 jobs)。`lake build Statements` — 生成 Statements。`lake build naru_test` / `lake exe naru_test <群>` — 検査ドライバ(lean_lib `NaruTest` = `tests/NaruTest.lean` + `tests/NaruTest/*.lean`、入口 `tests/NaruTestMain.lean`。`Common.lean` に `ok` / `fail` / `runProc` / `runGroup` / `sourceRoots`(naru.toml のルート))。群は `grammar`(C16)/ `zed`(C17)/ `lsp`(C18)/ `zed-install`(C19)/ `golden [--finality-horizon N]`(C10)/ `statements`(C8 / C9)/ `repo [--base-commit <sha>]`(C21 / C23 / C25。17 項目、約 1 分。基準コミットは既定で IDEAL.md の前提から読む)。
- `lake exe naru compile` — naru.toml の各ルートを 1 単位として検査し、`generated/Model` と `generated/Statements` を消してから作り直す(C1)。`naru-unit` は全ソースの hash なので、ソースを 1 つ足すと全ヘッダが変わる。コンパイラ(`compiler/**/*.lean`)や stdlib を変えても全ヘッダが変わるので、コンパイラを変えた周回は最後に `compile` し直してから C1 を取る。何も変えていなければ再生成後の `git status --short generated` は空。`compile [--out <dir>] <files...>` は検査だけ(`--out` でそこに出力)。診断は stderr に `file:line:col: error[E0xx]: msg`、exit 1。
- `lake exe naru check-reject <file.naru> <Exxx>` — 反例が拒否されかつ診断に `Exxx` を含めば PASS で exit 0(台帳の `cycle N:` 出典に使える形)。
- `lake exe naru simulate specs/consensus/scenarios/<name>.naru` — ルート全体を検査して `generated/` を作り直し、`.lake/naru/simulate/Simulate.lean`(`main`。lakefile の lean_exe `naru_simulate` の `srcDir`。C26: `generated/` には compile の出力だけ)を書いて `lake build naru_simulate` → `.lake/build/bin/naru_simulate`。ルート外のファイル・scenario の無いファイルは exit 2、診断は exit 1。basic の出力は周回 16 以来同じ(t = 10 で confirmed 2、t = 30 で confirmed 7 / stable 4、F 0)。README のクイックスタートの抜粋はこの出力の行(`naru_test repo` が照合する)。scenario の書き方は `docs/language.md`「scenario と observer」。
- C10 の golden test: `tests/golden/Golden.lean`(手書き Model と生成 Model を 1 プログラムから import)を `LEAN_PATH="$(cd third_party/verified-consensus && lake env printenv LEAN_PATH):$PWD/.lake/build/lib/lean" lean --run tests/golden/Golden.lean [--finality-horizon N] [--side hand|gen]` で走らせる(`lean --run` は lake のロックを取らない)。ドライバ `lake exe naru_test golden`(引数なし = horizon 100 = **C10 の証拠**。手書き側 interpreter で約 8 分、全体約 9 分(機械の負荷で 21 分になることもある)。`--finality-horizon 40` は約 27 秒の回帰で `note:` が出る)。16 case(Witnesses 4 run + scenario 5 本 6 run + observe の結び付き 6)。FinalityLiveness の全 horizon(33,729)は両 Model とも実行不能(周回 21 の計測: 手書き 100 tick 502 秒、tick 費用は木のサイズの 3〜4 乗)。Lean の癖: 純粋な `let` の計時は `IO.lazyPure` で固定、閉じた項は 1 度だけ評価される。

## コンパイラの事実
- 段: 字句 → 構文 → 名前解決・phase(`Resolve.lean`: E001, E011〜E013)→ 型・capability + Core IR(`Typecheck.lean`: E003〜E006, E014〜E016, E018, E019)→ 停止性(`Totality.lean`: E002)→ Model backend(`Backend/Model.lean`: E017)→ Statements backend(`Backend/Statements.lean`)。前の段に誤りがあれば次に進まない。`import` は受理するだけ。名前解決はコンパイル単位の 1 つの大域表(同名の fn はファイルが違っても E012。欄名・variant 名は大域表に入らないが Lean の自動生成名 `rec` `mk` … は不可)。詳細は `docs/architecture.md` と `docs/language.md`。
- stdlib メソッドの追加は 3 箇所: `Typecheck.lean` の `*Sigs` 表、`Backend/Model.lean` の `emitMethod`(`Table` / `Set` は `NaruStd.Table.<名前>` に自動で落ちる)、`docs/language.md` の表(+ `tests/accept/backend.naru` に受理例)。構文を増やしたら `docs/language.md`・パーサ・tree-sitter 文法を同じ周回で(`docs/editors.md`)。
- `Naru.sha256Hex`(`Sha256.lean`)は `shasum -a 256` と一致。版 `naruVersion`(`Main.lean`)は `lakefile.toml` の `version` と合わせる。
- 移植の対応表(手書き Lean → naru の写し方)と手書き Statements の構成は `docs/architecture.md`「verified-consensus の Statements の移植」と各ファイルの冒頭コメント。手書き Witnesses の 4 run はすべて tick だけ(deliver 無し)。移植ソースの行数の分母(IDEAL.md の 1.5 倍判定)は約 6,850 行(`find specs/consensus -name '*.naru' -not -path '*/scenarios/*' | xargs cat | wc -l`)。

## 環境の癖(周回の中)
- Bash から `.idd/` や `IDEAL.md` に触れる(ls・grep のパターンに含めるのも)と hook が拒否する。コマンド文字列に `idd`(入れ子起動の禁止)や `rm -rf` を含むと拒否される(一時ファイルの掃除は別名のディレクトリか `mv` で)。ルートで引数なしの `ls` は timeout になる(`git ls-files` やサブディレクトリの `ls` を使う)。記録・台帳・知見は Write ツールで書く。
- git フックは `GIT_CONFIG_*` の環境変数で全リポジトリに掛かる(`reference-transaction` が `refs/remotes/*` 以外の参照の作成・更新を拒否): `/tmp` への `git clone` / `git init` も HEAD を作れず失敗する。submodule の git リポジトリは周回の中では作れず、submodule の中で HEAD を動かす(基準コミットの更新の fetch / checkout)のも周回には無理 — 人間が周回の外で行う(周回 26 → 人間の commit 37d302d)。`.gitmodules` の Write はハーネスが拒否する。
- 回帰で `.lake/naru/scratch/cNN/` を一時ファイルの置き場に使う(追跡対象外)。`generated/` に追跡対象外のファイルを残さない(C26)。
