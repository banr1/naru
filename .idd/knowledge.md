## ビルドと実行(リポジトリのルートで)
- `lake build` — naru コンパイラ(`compiler/`、lean_lib `Naru` + lean_exe `naru`。依存なし、冷えた状態で約 40 秒)。`lake build NaruStd` — Model 用 stdlib(`stdlib/Model`。変えたら先にこれ)。`lake build Model` — 生成 Model(`generated/`。C6 の検証。21 モジュールで 29 jobs、数秒)。
- `lake exe naru compile` — `dsl/**/*.naru` を検査し、`generated/Model` を消してから `generated/Model.lean` + `generated/Model/**.lean` を作り直す(C1 の検証。古い生成ファイルは残らない)。ヘッダの `naru-unit` は全ソースの hash なので、ソースを 1 つ足すと全生成ファイルのヘッダが変わる(本文は変わらない)。
  `lake exe naru compile <files...>` は検査だけ(`--out <dir>` を付けるとそこに出力)。診断は stderr に `file:line:col: error[E0xx]: msg`、exit 1。
- `lake exe naru check-reject <file.naru> <Exxx>` — 反例が compile で拒否されかつ診断に `Exxx` を含めば PASS で exit 0(台帳の `cycle N:` 出典に使える形)。検査スクリプトは Lean で書く前提なので、シェルのラッパーは置かない。

## コンパイラの事実
- 段: 字句解析 → 構文解析 → 名前解決・phase 検査(`Resolve.lean`: E001, E011〜E013)→ 型・capability 検査 + Core IR への elaboration(`Typecheck.lean`: E003〜E006, E014〜E016。`infer` が `(型 × Core.Expr)` を返す)→ 停止性検査(`Totality.lean`: E002。受理した再帰の測度を backend に渡す)→ Model backend(`Backend/Model.lean`: E017)。前の段に誤りがあれば次の段には進まない。
- Core IR(`Core.lean`)は型付き・名前解決済み・糖衣展開済み。`TyV` はここで定義(型別名は展開済み、メタ変数は Core には残らない: 残れば E014)。
- stdlib メソッドの追加は 3 箇所: `Typecheck.lean` の `*Sigs` 表(型変数 `$T` `$K` `$V` `$E` は受け手で束縛、`$U` は呼出しごとに fresh)、`Backend/Model.lean` の `emitMethod`(Lean core の名前か `NaruStd.*`。`Table` / `Set` は `NaruStd.Table.<名前>` に自動で落ちるので NaruStd に def を足すだけ)、`SYNTAX.md` の表(+ `tests/accept/backend.naru` に受理例)。Lean 4.34.1 の `List.flatMap` / `List.filterMap` は関数が先の引数順。
- E002 が受理する再帰は 2 形だけ: match の構築子パターンで取り出した部分項への構造的再帰(再帰呼出しが別の fn / stdlib メソッドの実引数の中にあってもよい: `ats.toSet().union(chainAttestations(p))`、`[b].append(chainUp(n - 1, p))`)と、`n ≥ k` が分かる分岐内で Nat 仮引数(または match の bind 別名)を `n - k` で渡す fuel(`else` の中の `match` の腕からでもよい)。下限は `if` の条件(`==` `!=` `<` `<=` `>` `>=` とリテラル、`!`、`&&` の then、`||` の else、`else if` の連鎖)と、`match n` のガード無しリテラル腕(0 から連続して覆った値の次)と腕のガードから取る。サイクル(相互再帰)は全辺で同じ測度が厳密に減ること。`let` 経由・record の欄・lambda 内・Int・関数値の受け渡し・辞書式の測度は E002(保守的)。lambda の中から再帰しない fn を呼ぶのは自由。
- 関数型の仮引数(周回 6): `fn f(score: (Block) -> Nat, …)`、多引数も `(Option<BlockId>, Block) -> Bool`。`Ty.fn` は fn / observer / spec 宣言の仮引数・closure の引数・`let` の注釈にだけ許す(欄・variant・別名・戻り型・input・コレクションの中・`() -> U` は E014)。本体の `score(b)` は Core の `callLocal`。`let score: (Block) -> Nat = |b| …;` と注釈付きで lambda を束ね、`score(h)` と呼び、別の lambda に捕獲させ、関数型の仮引数に渡せる(周回 9: `updateConfirmationWith`)。停止性: 関数値の呼出しは辺にならず、fn を値として参照した場所が `bare` 辺になるのでサイクル内なら E002。backend は `(«score» : (A → B))` と `«score» b` を出す。`_e` のような未使用の仮引数は Lean の警告にならない。
- backend が Lean に落とす形は SYNTAX.md「Core IR と Model backend」。fuel は `if _h' : c` + `termination_by n` + `decreasing_by …`、`Nat` の match は `match _hm' : n with`、ガードは Option の match、構造的は `termination_by structural p`。宣言は参照の依存順に並べ替えて出す(ソース内の前方参照は可)。引数 0 個の fn(`pendingFrame()`)は Lean では値 `def pendingFrame : Frame`。`input` を(推移的に)使う fn は先頭に `名前'` の関数引数を持つ(完全修飾名の辞書順: `tick (committee' proposer' awake' newRoot')`。生成ファイルの `def` の先頭行で確かめる)。生成コードの Lean 組み込み名は完全修飾、局所名・欄名は `«»`。
- 名前解決はコンパイル単位(渡された全ファイル)を 1 つの大域表で行う。`import` は受理するだけで意味を持たない(backend はモジュール間の参照から `import` を計算し、循環は E017)。同名の fn はファイルが違っても E012(移植では `named…` / `sgTo…` / `storePool` / `storeTau` / `initStore` のように改名して逃げる)。欄名・enum の variant 名は大域表に入らないので fn や型と同名でよい(`grades.anchor` は欄、`anchor(e, …)` は fn、`NamedObject.Block(b)` の variant と型 `Block`)。仮引数・lambda 引数は同名の大域 fn を隠す(`early` / `late` / `anchor` を局所名に使える)。予約語(`input` `record` `module` `state` …)は局所名にも使えない(`inp` / `rec` / `post`)。
- 大文字始まりの経路は大域名(`Phase.Tick`、`Set.empty`)、小文字始まりは値と欄の連鎖。局所名は小文字か `_` 始まりのみ(大文字は E010)。`x.f(args)` は `f` がユーザ宣言の大域名なら `f(x, args)`(UFCS)、無ければ stdlib メソッド。record literal は `if` の頭部に直接書けない(`let` に束ねる)。`type Alias = Record` は型の位置でどこでも使えるが、literal / update は元の record 名で書く。record literal の入れ子 update(`NamedStore { core: Store { t: t, ..st.core }, ..st }`)は可。
- tuple は n 要素(`(A, B, C)` → Lean の右結合 `A × B × C`、`Option (Height × BlockId × Bool)` と同じ型)。パターンは入れ子可(`Some((h, entry, _))`、`Some(Some(r))`、`Vote(h, entry, true)`)。tuple の射影は無いので戻り値の組は `match f(x) { (a, b) => … }` で取り出す。`match` の scrutinee には `if` 式も置ける(`match (if c { f(x) } else { (x, None) }) { (a, b) => … }`)。`match (a, b) { … }` の網羅性は Lean が検査する。
- 組み込み: primitive 型名、`Some` `None` `Ok` `Err`、自由関数 `sort` `choose` `pick`(再宣言は E012)。`unknown` 型は診断を出した後にだけ作る、が不変(型の位置の経路は完全一致で解決。崩れると E003 / E004 が素通りする)。Int リテラルは Int が期待される位置(`-> Int` の match の腕の `-3` も)で Int。
- capability: `eq` は primitive と derive eq の record/enum とその合成、`order` は Nat/Int/String・Option/List/tuple・derive order の record/enum。Set/Table/関数型は order も eq も持たない。Set → List は `sort(by = …)` だけ。`Set.sum` / `List.sum` と `Set.flatMap` は Set から直接取れる。`List.flatMap` / `List.filterMap` / `Table.mapValues`(鍵を保って値を写す。全域写像の合成の移植先)は周回 9。メソッドの cap 検査は受け手の型で即時、`Set.of` / `Set.singleton` の要素の `eq` は宣言の終わりに検査する。backend は `eq` に `DecidableEq` と隠れた `Ord` を、`order` に `Ord` を、常に `Repr` を生成する。`Set<(Height, BlockId)>` / `Option<Option<Block>>` / `Table<Round, Set<SGVote>>` / `Set<Option<BlockId>>` も通る。
- `Naru.sha256Hex`(`Sha256.lean`)は Lean 実装。`shasum -a 256` と一致を確認済み。コンパイラの版 `naruVersion`(`Main.lean`)は `lakefile.toml` の `version` と合わせる。stdlib の hash は `stdlib/Model/**/*.lean` の内容から計算する(版は目印)。

## Lean 4.34.1 の癖
- `syntax` と `meta` は予約語。`String.mk` は非推奨。docstring `/-- -/` は `mutual` の前に置けない。到達しない match の alternative は **error**。`deriving DecidableEq` / `Ord` は入れ子の帰納型(`Option<Self>` 越し)に使えない。`{ x with }`(欄なし)は使わず `x` を出す。
- 手書き側の fixture: `{ fg with sg_votes := …, live_confirmed := b3 }` のように `extends` 越しの親の欄も `with` で直接更新できる。`GradeRead`(`rawG2 : Prop` + `rawG2_decidable`)は `rawG2` だけを `with` で変えられないので `⟨anchor, none, clear, False, inferInstance⟩` と作り直す。`CleanFrom` には Decidable instance が無い(`instance … := by unfold CleanFrom; infer_instance` を test 側に置く)。`Finset.sort` / `Finset.image` / `Finset.biUnion` は `#eval` できる。
