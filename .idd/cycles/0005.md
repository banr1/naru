## 選択
C10 に向けた移植の次の塊として Objects 層を選んだ。理由: (1) 必須の unmet はすべて移植が根で、移植の先頭(Objects)が依存の根。(2) 移植で naru に足りない機能が早く露わになり、言語の判断(型引数を入れるか、固定するか)を小さな対象で決められる。(3) C1 / C6 はその出力で同じ周回に取り直せ、手書き Model の olean があるので値の一致(golden test の予行)まで観測できる。C7(simulate)は移植済み protocol が無いと met にできないので後に回した。
設計の判断(IDEAL.md 不変条件「言語機能・stdlib の追加は周回の判断」の範囲): 型引数付きの宣言は加えず、`V` は `record ValidatorId { value: Nat } derive eq, order` に固定(Model が V に要るのは等しさと正規化の順序だけ。`Fin n` の値は `value` で写せる。naru の表現力を Lean より小さく保つ側に倒した)。`WithBot Time` は `enum Stamp { Bottom, At(Time) } derive order`(variant 宣言順で Bottom が最小)、`Occurrence = Option<Stamp>`(None = +∞)。`TimestampMap α` は使う側で `Table<T, Stamp>` + `occurrenceBefore(ts.get?(x), Γ)`。環境のオラクル(`proposer` / `committees`)は `input`、有限型上の関数 `weight : V → Nat` は `Table<ValidatorId, Nat>`(`totalWeight` は keys の和)。証明の欄は Statements の premise に回す(理想化)。`Set.sum` は可換な集約で順序に依存しないので Set から直接取れるようにした(E003 / E004 は緩めていない。`fold` は E004 のまま)。大域表が 1 つなので Block と NamedBlock の同名 fn は NamedBlock 側を `named…` に、`Block.find?` は `findRoot?` に改名した。
