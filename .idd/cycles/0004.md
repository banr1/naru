## 選択
C1(Model backend の最小版)を選んだ。理由: (1) 必須の unmet(C1・C6〜C10)はすべて backend を要し、C1 がその根。(2) C6 はその出力をビルドするだけなので同じ周回で検証でき、C7 以降の土台になる。(3) 前提「必ず小さな Core IR を経由する」に従い、Typecheck を Core への elaboration に拡張するのが最小の構造。
設計の判断(IDEAL.md の不変条件「言語機能・stdlib の追加は周回の判断」の範囲): `Set` / `Table` は要素の `Ord` で正規化した重複なしの昇順リスト(等しい集合は同じ表現 → `DecidableEq` が集合の等しさに一致。計算可能・決定的・mathlib 不要)。そのために backend は `derive eq` の型に `DecidableEq` と隠れた `Ord`(宣言順の辞書式)を生成する(naru ユーザには露出しない)。`input` は Lean の宣言にせず、推移的に使う fn の先頭の引数 `name'` にして引き回す(モジュールを跨ぐ 1 つの構造体は循環 import になる)。`match` のガードは Lean に無いので Option の match に落とし、再帰 fn の Nat の match は `match _hm' : n with` の等式で停止性証明に事実を残す。Lean の `deriving` が入れ子の帰納型(`Option<Self>` 越し)に使えないので、そのような型は E019 で拒否(言語を Lean より小さく保つ側に倒した)。最後の腕のガードと Nat / Int / String の match の穴は E018 で拒否(網羅性の穴が `panic!` に落ちるのを防ぐ)。
対象ソース(前提)は `dsl/` の移植なので、手書き Model の `Objects/Identifiers.lean` を最初の 1 ファイルとして移植し、それに対して C1 / C6 を検証した。移植が進む周回ごとに取り直す。
